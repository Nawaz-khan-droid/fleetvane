**Recommended Navigation Layout**

- **Main Menu (Left/Center Align):**
  - **Features:** Group your core tools here (e.g., *Real-Time GPS, Fuel Tracking, Maintenance, Driver Safety*). You can use a dropdown menu if you want to list specific fleet types (like Trucks, Vans, or Construction).
  - **About / Help Center:** Keep "About" for company credibility and "Help Center" so existing customers can easily find customer support or documentation.
- **Action Buttons (Right Align):**
  - **Login / Sign Up:** This makes it easy for existing users to access the platform and new users to register.
  - **Book a Demo (CTA):** Make this a highly visible, contrasting button. This is your primary **Call to Action (CTA)** because B2B fleet buyers rarely buy software without seeing a demo first.

**A Quick Tip on "HomePage" in the Menu**

You **do not need a text button that says "HomePage"** in your navigation. Instead, place your company/product logo on the far left. Users universally expect that clicking the logo will take them back to the home view.

🔒 The 3-Step Secure Password Reset FlowTo prevent security leaks while keeping the workflow intuitive, structure your backend logic using these stages:The Validation Gate: The user submits their phone number or email. The system runs a search: SELECT user_id, role, is_active FROM users WHERE phone = input_phone. If the user exists and is active, the system generates a secure, randomized payload token.The Verification Gate:If Phone: The system sends the 6-digit OTP code through an SMS gateway (like Twilio). The user enters it into an OTP verification screen.If Email: The system sends a reset link.The Secure Reset Gate: Once verified, the app displays a "Set New Password" form. The system updates the hashed password value in the database, invalidates the old device token / UUID session, and forces the user to log back in normally with their new credentials to confirm their security.

- Note: We Use GPS Tracking and Real-Time Mapping
We do logging the IP address serves as an essential security audit log to prevent fraudulent logins
Smartphones do not have permanent public IP addresses. Their network addresses shift constantly for several reasons:Cell Tower Switches: As a driver moves across town, their phone disconnects from one cell tower and connects to another. Each tower assigns a new temporary local IP address.Network Switching: If a driver goes from using office Wi-Fi to mobile 4G/5G data, their public IP address changes instantly.Cellular Carrier Rotation: Mobile internet providers (like Jio, Airtel, or Vodafone) use dynamic IP allocation. They rotate and reassign IP addresses automatically every few hours or whenever the phone reconnects to the network to save available network space.What This Means for Your FMS Security LogsDo not use an IP address as a permanent device ID. You cannot rely on an IP address to recognize the same driver tomorrow or next week.Use it as a single-event security stamp. Logging the IP address during sign-in only tells you where the network connection originated at that exact minute. It is useful for spotting weird login spikes (like a login happening from a different country), but expect that same driver to have a different IP address tomorrow.
To accurately identify a driver’s device even when their IP address changes constantly, you should use a Device ID (UUID) combined with a secure Refresh Token.When a driver logs in for the very first time, the platform generates a unique, permanent string (a Universally Unique Identifier, or UUID) and saves it inside the app's secure long-term storage (like EncryptedSharedPreferences on Android, Keychain on iOS, or localStorage in a browser). This ID remains exactly the same even if the driver switches from Wi-Fi to cellular data, drives across states, or reboots their phone.
Exact Implementation Mechanics For Your Tech Team1. The Audit Log (IP Capture)The moment a driver clicks "Log In", your server scans the network request header (X-Forwarded-For or req.socket.remoteAddress).Database Record: It creates a record inside your system database that maps: user_id | ip_address | login_time | device_signature.The Use Case: If a driver claims they couldn't complete a route because the app failed, but their IP log reveals they logged in from a completely different region, your Fleet Manager has clear security records to investigate fraud.2. The Multi-Tier Permission GateTo ensure the system works seamlessly, the driver must pass two distinct checkpoints:The System Settings Level: The app reads the device’s system variables. If the phone's overall location toggle is off, the app locks the screen with an overlay explaining how to open the phone’s native settings menu to switch it on.The In-App Consent Level: A beautifully designed pop-up must state clearly: "We track your location exclusively while you are en route to a delivery to update your manager. By clicking agree, you authorize this tracking." The action is saved with a timestamped database flag (gps_consent_granted = true).3. Battery & Privacy ProtectionBecause continuous mobile GPS streaming consumes vast amounts of phone battery, your system should use a variable heartbeat. When the driver is actively driving (speed > 15km/h), ping the location every 15 seconds. If the vehicle is stuck in traffic or stopped at a delivery point, automatically step down the ping rate to every 60 seconds to prevent draining the driver's phone battery.
